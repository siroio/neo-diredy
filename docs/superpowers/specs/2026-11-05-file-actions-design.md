# neo-diredyの単体・一括ファイル操作

作成日: 2026-11-05。状態: ユーザー承認済み、実装・検証まで継続。

## 目的と合意済みの範囲

ユーザーはReveal、コピー、切り取り、削除と一括操作を優先して改善したい。
「選択→コピー／切り取り→別フォルダーへ移動→貼り付け」の方式を選び、
単体でも一括でも同じ操作を使うことを求めている。
クリップボードはまずneo-diredy内で完結させることを確認済み。

対象はneo-diredy/のみ。既存のREADME.md、neo-diredy.el、
tests/neo-diredy-workflow-tests.elにあるディレクトリ移動後のバッファ整理の差分を保持する。
親リポジトリ、emacs.d、実環境の設定・導入済みコピーは変更しない。
stage、commit、pushは行わない。

## 比較した方式

1. 標準Diredのコピー・移動・削除を共通メニューから呼ぶ。変更は小さいが、
   操作ごとに行き先を入力する流れは残る。
2. コピー・切り取りの対象を保持し、移動先で貼り付ける。待機状態と部分失敗の管理が
   必要になるが、単体／一括を同じ手順で扱える。

ユーザーは2を選択。Diredの標準コマンドとマークを引き続き利用できるようにする。
ユーザーはこの設計を承認し、常時表示する文字を増やしすぎないことを追加指定した。

## 操作対象

- 現在のDiredバッファの通常マークを対象にする。マークがなければカーソル位置の1項目。
- Diredの削除予定フラグは通常マークに含めない。空ディレクトリや非ファイル行は0件。
- 操作開始時に対象の絶対パス一覧を確定し、カーソルやマークの後続変更に追従させない。
- ローカルのファイル、ディレクトリ、シンボリックリンクを扱う。リモート操作とWDired編集中は実行しない。
- 同じパスは重複排除する。親ディレクトリとその配下を同時に選んだコピー／移動／削除は
  親にまとめ、実際の対象件数と、配下を含む旨を示す。Revealでは明示した項目を維持する。
- 貼り付け先は現在表示中のDiredのdefault-directory。選択中のサブフォルダーには暗黙に貼り付けない。
- 操作前に存在とパスを再確認する。リンクはリンク自身を扱い、再帰処理でリンク先をたどらない。

## 選択と操作メニュー

既存の3ペインと下部modelineを維持する。中央ヘッダーに現在の対象件数を表示し、
待機状態も中央ヘッダーへ短く集約する。通常時はパスだけ、選択時に選択件数、
コピー／切り取り待ちのときだけ種別と件数を付ける。説明と操作キーはメニュー内に置く。
ユーザーの文字量に関する追加指示を優先し、常設の状態行は増やさない。
既存mode-line-formatは変更しない。
通常マークの行と切り取り待ちの行を、
文字による印とテーマを継承したfaceで区別し、色だけには依存しない。
ファイル名本文には表示用文字を挿入せず、WDiredの編集を壊さない。

提案キーはC-c fで共通アクションメニュー。既存のchild-frame選択UIを拡張し、
通常の上下・Enter操作に加えて表示された1文字で実行できるようにする。
既存のopener／bookmarkメニューの操作は変更しない。

| メニューキー | 操作 |
| --- | --- |
| c | 対象をコピー待ちにする |
| x | 対象を移動待ちにする（切り取り） |
| v | 現在のフォルダーへ貼り付け |
| d | 対象を削除 |
| r | 対象をExplorerで表示（Reveal） |
| ? | 操作対象の一覧を確認 |
| m | 現在行の通常マークを切り替え |
| a | 現在の一覧の全項目を通常マーク |
| u | 通常マークをすべて解除 |
| q | コピー／移動待ちを解除 |
| Esc / C-g | メニューを閉じる |

タイトルには対象件数を表示し、vには貼り付け元件数とコピー／移動の区別を付ける。
使えない操作は理由とともに無効表示し、選択でエラー画面へ飛ばさない。
対象一覧の確認をメニューから開けるようにし、長い一覧でも全件を確認できるようにする。
メニューを開くことでDiredのマーク・カーソル・スクロール位置を変更しない。
各操作はM-xからも呼べる公開コマンドにする。
標準DiredのC/R/DなどとEvilの既存y/x/p等を置き換えない。

## 内部クリップボード

Emacsセッション内で共有するコピー／移動の種別と絶対パス一覧を持つ。
別ディレクトリへの移動、Diredバッファの自動整理、プレビューを閉じる操作で消失させない。
新しいコピー／切り取りで置き換え、明示的な待機解除・パッケージunload・Emacs終了で解放する。
kill-ring、OSクリップボード、ディスク上の保存データは使わない。
ファイル操作や元バッファの保持はコピー／切り取りを登録した時点では行わない。

コピー成功後もクリップボードを維持し、複数の行き先に繰り返し貼り付けられる。
切り取りでは移動に成功した項目だけを外し、スキップ・失敗・未処理の項目を残す。
全件成功時に待機状態を解除する。途中で別のクリップボードを設定できる実装にする場合は、
古い操作の終了処理で新しいクリップボードを上書きしない。

## 貼り付け・削除・結果

事前に対象一覧と行き先を確定し、コピー／移動はEmacs/Diredの既存ファイル操作を利用して逐次実行する。
別の非同期ファイル転送エンジンや独自ジョブ管理サービスはこの版では導入しない。
項目単位の進捗と中断を用意するが、巨大な単一ファイルの処理中の応答性やバイト単位の進捗は保証しない。
既存の非同期プレビュー・Git取得は維持する。

- 元と先が同一、またはディレクトリを自分の配下へ貼り付ける場合は実行しない。
  Windowsの大文字小文字と、既存の親を経由したリンク／ジャンクションの解決を考慮する。
- 同名ファイルは「スキップ／別名／上書き／中断」を選ぶ。既定はスキップ。
  同種の通常ファイルに限り、残り全件へ同じ選択を適用できる。
  同名ディレクトリへの暗黙の結合や、ディレクトリ・ファイル間の置き換えは行わず、別名またはスキップを選ぶ。
- 複数の元ファイルが同じ行き先名になる場合も衝突として扱う。
- 削除はdelete-by-moving-to-trashに従い、実際の動作を「ゴミ箱へ移動」または「完全削除」と表示する。
  全対象と件数、ディレクトリ配下を含むことを確認してから処理する。
  ゴミ箱への移動に失敗した場合に無断で完全削除へ切り替えない。
- 個別の失敗は記録して後続を処理し、ユーザーの中断では後続を止める。
  完了／スキップ／失敗／未処理を区別する。中断を全件取消や成功と報告しない。
- 部分コピーが残った場合は行き先と状態を報告し、自動で元ファイルや既存の行き先を削除しない。
  移動成功は元がなくなり行き先が存在するという結果も確認して判断する。
- 完了時は件数を短く表示し、失敗・スキップ・中断の詳細を確認できる結果バッファを用意する。
  全件成功は通常のmessageで足り、無用に結果画面へ切り替えない。
- 影響する既存のDiredバッファを更新する。無関係なマーク、選択位置、編集中のバッファは維持する。
  対象ファイルの未保存編集は破棄せず、標準Dired相当の扱いを維持する。

## Reveal

Revealはファイル／フォルダー自身の所在をExplorerで選択して表示する意味とする。
フォルダーの中を開く既存openerのShow in Explorerとは区別する。
一括Revealは親フォルダーごとにまとめ、同じ親の対象をまとめて選択する。
異なる親を含む場合は、開くフォルダー数を実行前にメニューで示す。

WindowsのSHOpenFolderAndSelectItemsを使う方式を実装候補とする。
既存の1件用Explorer起動をN回繰り返して済ませない。
追加の配布DLLは導入せず、必要ならWindows付属PowerShellから固定のヘルパーコードを実行する。
パス一覧はUnicodeのデータとして渡し、ユーザーパスをコードやシェル文字列に展開しない。
ヘルパー起動の失敗と親ごとの失敗を結果へ返す。
Windows以外は理由付きの無効表示とし、ファイル操作全体はWindows専用にしない。

参考: https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shopenfolderandselectitems

## 実装者に任せる事項

内部データ構造、関数分割、face名、ヘッダーの幅不足時の省略、結果バッファの形式は任せる。
既存のneo-diredy.elとテスト構成を基本とし、ファイル分割や新しい依存を目的にしない。
現行のpackage-install-fileでもRevealを含めて動くよう、補助コードの配布方法を選ぶ。
初期版ではフォルダーを跨いで選択を蓄積する買い物かご、OSクリップボード共有、
汎用Undo、非同期転送キュー、リモートファイル、レイアウト全体の変更は含めない。

## 検証と完了条件

新しい操作のERTはtests/内の使い捨てディレクトリで行い、実ユーザーデータを使わない。
ゴミ箱とExplorer呼出しは通常テストでは代替し、実行する場合も作成した検証用データだけを対象にする。
PowerShell等を起動する検証のTEMP/TMPと生成物は対象リポジトリ内へ隔離する。
ユーザーinitや実行中のEmacsに接続しない。

1. 1件と複数件で同じ公開コマンドが動作し、通常マーク・削除フラグ・0件の規則が守られる。
2. ファイル／ディレクトリ／リンクのコピー・移動、日本語・空白・記号を含む名前が正しく扱える。
3. 同名衝突、同一元先、自分の配下、親子重複、消失した元、途中失敗・中断でデータと待機状態が正しい。
4. 削除の対象確認、取消、ゴミ箱失敗、未保存編集の保持を確認する。
5. Revealの親ごとのグループ化、Unicode引数、失敗結果を検証する。
6. マークと待機状態の表示、メニューの対象一覧、既存opener・bookmark・Evilのキーを確認する。
7. バッファ自動整理、WDired、レイアウト、modeline、プレビューの関連回帰テストとpackage checkを行う。
8. 隔離GUIでchild-frameと実キー相当の操作を確認する。Explorer実画面、物理キー入力、
   実ユーザー設定での検証は自動テストと区別し、未確認なら明記する。

変更予定はneo-diredy.el、README.md、操作用の新規テスト、必要な既存関連テスト、設計・計画文書。
製品実装と検証へ移る前にこの設計を確認する。

## 設計レビューと画面案

独立した実装者視点のレビューで、実装計画に必要な未決の重要事項なしとの結果を得た。
ユーザーが画面案の表示を希望したため、.bench/brainstorm/file-actions-20261105/content/file-actions.htmlに
単体・3件選択・切り取りと貼り付け・部分失敗を切り替えられる使い捨ての画面案を作成した。
画面案の操作はサンプルデータだけに作用し、実ファイルやOSクリップボードは変更しない。
配色・ブラウザー用のナビゲーションボタンは説明用であり、そのままEmacsへ移植するものではない。
