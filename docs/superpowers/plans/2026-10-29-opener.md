# Child-frame Opener Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open the selected item through an extension-aware child-frame menu.

**Architecture:** Keep the package's single-file structure. Build candidate
actions from a small customization variable; reuse the buffer-local key mode,
native child frames, Windows associations and direct process arguments.

**Tech Stack:** Emacs Lisp, Emacs 29.1+, Windows, ERT, optional existing Evil.

**Spec:** `../specs/2026-10-29-opener-design.md`

## Global Constraints

- No additional dependencies or imports from Yazi.
- Work only in neo-diredy; preserve existing uncommitted changes.
- Do not stage, commit, create a worktree or edit real user settings.
- Keep ordinary Enter behavior and Emacs 29.1 compatibility.

## Review Focus

- Unicode, spaces and command punctuation must remain a single file argument.
- Nonexistent targets, unfinished WDired edits and remote paths must not launch.
- Cancel, quit, input errors and frame creation errors must not leak UI objects.
- Long/many candidate labels must remain navigable in the child frame.
- Disabling neo-diredy must restore Shift+Enter with and without Evil.
