# neo-diredy

標準Diredを、親ディレクトリ・現在の一覧・プレビューの3カラムで表示するEmacsパッケージです。Dirvish、Evil、Dired Previewは必須ではありません。

```text
Parent             ~/project/                    Preview
  docs/              src/                        選択したファイルの内容
▸ project/         ▸ README.md                    またはディレクトリ一覧
  tools/             LICENSE
```

## 導入

Emacs 29.1以降が必要です。Diredを含む依存ライブラリはEmacsに同梱されているため、追加パッケージのインストールは不要です。検証環境はWindows / Emacs 31.1です。

`M-x package-vc-install` を実行し、次のURLを指定してインストールします。

```text
https://github.com/siroio/neo-diredy
```

インストール後、Emacsの設定に次を追加してください。

```elisp
(with-eval-after-load 'dired
  (require 'neo-diredy))
```

この設定でDiredを開くと、自動的に3カラム表示になります。パッケージの読み込み時に `neo-diredy-mode` が有効になるため、毎回コマンドを実行する必要はありません。

ローカルにチェックアウトしたソースを使う場合は、代わりに次の設定を追加します。パスは実際の配置先に変更してください。

```elisp
(add-to-list 'load-path "C:/path/to/neo-diredy")
(with-eval-after-load 'dired
  (require 'neo-diredy))
```

`M-x package-install-file` で `neo-diredy.el` を直接インストールすることもできます。その場合も、上記の `with-eval-after-load` の設定を追加してください。

旧 `neo-dired-yazi-mode` とは併用しないでください。移行前に旧モードを無効にし、旧モードの自動有効化設定がある場合は取り除いてください。

## 操作と表示

- 中央の一覧は標準Diredのバッファです。移動、マーク、コピー、リネーム、削除、再読込など、標準Diredの操作をそのまま使えます。Evilを使用している場合も、既存のDired用キー設定が使えます。
- WDiredによるファイル名編集でも3カラムを維持します。Evil Collectionの `i` で入るINSERT状態や、InsertキーでのREPLACE切り替えにも対応します。編集時はカーソルを表示し、確定前のプレビューは元ファイルを参照します。確定は `C-c C-c`、取消は `C-c ESC` です。
- 操作後もコンパクトな表示を維持します。権限・所有者などの詳細を表示して操作したい場合は、`neo-diredy-mode` をオフにしてください。
- `M-x neo-diredy-mode` で通常のDired表示へ戻せます。同じコマンドで再び有効にできます。
- ディレクトリ移動時は、次の画面描画までに表示を整えます。カーソル移動時のプレビューは0.12秒待ち、連続した移動による更新をまとめます。
- ファイルを開くと補助欄を閉じます。タブを切り替える前にも閉じ、空の補助欄を保存タブに残しません。
- 別の画面がウィンドウを追加・再利用したときは、neo-diredyの補助欄だけを閉じます。ヘルプやプラグインが開いたウィンドウを、以前の画面構成で上書きしません。Neo Gitでは画面構成を保存する直前に補助欄を閉じ、終了後にDiredへ戻れるようにします。Neo Git自体を依存パッケージとして読み込むことはありません。
- ヘルプなどを開いてDiredが選択されたままの場合は、3カラム表示の自動再作成を保留します。ヘルプを閉じる、別画面からDiredに戻る、元の画面構成に戻す、Diredでカーソルを移動する、Diredを開き直す、といった操作で再開します。M-xを開いて取り消すだけでは再作成しません。
- 一度に表示できる3カラムのレイアウトは1つです。幅72桁未満のウィンドウとリモートディレクトリでは通常のDiredを使います。
- 配色は現在のテーマを継承します。選択行は `neo-diredy-selection` faceで調整できます。
- modelineは設定済みの `mode-line-format` を変更せず、3ペイン全体の下部左端から表示します。行・桁、メジャーモード、文字コード、画像など、通常の表示をそのまま使います。modelineは同じDiredバッファを表示する専用ウィンドウに置き、中央のカーソル位置と同期します。`%p` などウィンドウの表示範囲に依存する項目は、下部ウィンドウを基準に計算されます。

## サイズとGit状態

中央の各行の右端に容量と2文字のGit状態を表示します。本文の中央寄せなど、他の設定が余白を調整しても、neo-diredyの中央一覧では右端の状態欄を確保します。中央ペインの幅が32桁未満の場合は右端の欄を省略しますが、選択項目の容量・Git情報は右ペインの詳細欄で確認できます。ファイル名は通常のDiredのままで、長い名前やWDiredの編集欄に表示用の文字を混ぜません。

右ペインの詳細欄では、Git取得中は `Git loading`、Git実行ファイルが見つからない場合は `Git missing`、ルートを取得できない場合は `Git unavailable`、状態取得の失敗・タイムアウトは `Git error` と表示します。`unavailable` はGit管理外のフォルダーでも表示されます。`g` で再取得できます。

```text
▸ src                 12.4 MiB  M
· README.md            3.2 KiB  M
· new.txt                128 B ??
```

- ファイル容量は一覧の属性から取得します。単位はB・KiB・MiBなどです。
- フォルダー容量は選択時に別のEmacsプロセスで再帰集計します。隠しファイルも含め、シンボリックリンクは辿りません。ディスク上の占有容量ではなく、通常ファイルのバイト数の合計です。リンク自身は `link` と表示します。
- 容量欄の `—` は未集計、`…` は集計中、`!` は取得失敗または30秒のタイムアウトです。読み取れない項目がある場合、途中までの合計を正しい容量として表示しません。
- 集計結果は最大64フォルダー分をレイアウト内で保持します。選択変更で進行中の集計を中止し、レイアウト終了時にキャッシュを解放します。
- Git欄の左はステージ済み、右は未ステージの状態です。`M` は変更、`A` は追加、`D` は削除、`R` はリネーム、`??` は未追跡です。競合は `UU`・`AA` などGitの表記を使います。フォルダー行は配下を集約し、同じ列に複数の状態がある場合は `*`、競合があれば競合を優先します。
- Git状態はPATH上の `git` を使って非同期で取得します。Gitが見つからない場合やリポジトリ外では欄を空にします。取得時間は30秒、出力は8,388,608文字までに制限し、上限を超えた場合や取得に失敗した場合もGit欄を空にします。
- 外部で変更した容量やGit状態を取り直すには `g` で再読込してください。Git状態はディレクトリ移動時にも取得します。

フォルダー集計を止める場合は `neo-diredy-directory-sizes`、Git取得を止める場合は `neo-diredy-git-status` を `nil` に設定して再読込してください。ファイル容量の表示は残ります。

## プレビュー

プレビューには専用バッファを使います。編集中のバッファを再利用せず、未保存の変更も破棄しません。ファイルのローカル変数や編集用フックも実行しません。テキストの構文ハイライトは行いません。

| 項目 | 既定値 |
| --- | --- |
| テキスト読込上限 | 64 KiB (`neo-diredy-preview-bytes`) |
| 画像ファイル上限 | 8 MiB (`neo-diredy-image-bytes`) |
| 補助欄のディレクトリ一覧 | 最大500件 |

画像はEmacsが対応している形式で表示します。大きい画像、未対応形式、バイナリファイルでは概要を表示します。同じファイルを再表示するときは、更新日時・サイズ・表示寸法などが変わらない限り読み直しません。外部で更新した内容を明示的に取り直すにはDiredの再読込 (`g`) を使います。

### 下部の詳細情報

右ペインの下部に、プレビューとは独立した最大3行の情報欄を表示します。画像や本文には重ねません。情報欄は右ペインの高さの1/4以内に抑え、本文を最低6行確保できない画面ではプレビュー見出し横の1行表示へ縮めます。画面サイズ変更にも追従します。補助欄に独自のmodelineや通常のバッファ用ヘッダーは表示しません。

| 種類 | 主な情報 |
| --- | --- |
| 画像 | 形式・元画像の寸法・取得できる場合は色深度 |
| 動画 | コンテナ形式・寸法・長さ・コーデック・平均fps |
| 音源 | コンテナ形式・長さ・サンプルレート・チャンネル数・コーデック |
| バイナリ | 判別できた形式・先頭16バイトの16進表示（狭い欄では8バイト） |
| テキスト | 拡張子・shebangから推定した言語、文字コード、改行形式 |

共通でファイルサイズと更新日時を表示します。フォルダー容量とGit情報も既存の非同期取得結果から反映し、取得完了時にカーソル移動なしで更新します。Git状態とブランチは3行目に表示し、長いブランチは短縮します。幅が足りない場合は項目単位で省略し、形式・サイズと種類ごとの主要情報を優先します。小さい画面の1行表示はGit状態・サイズ・形式の順に収まる項目を表示します。PSD/PSBはヘッダーの元キャンバス寸法、CLIPは抽出した画像の寸法を `Preview` と明記します。

ヘッダー・文字コード判定の読込は先頭64 KiBまでです。BOMがない文字コードは `(guess)`、一部だけ読んだ改行判定は `(sample)` と表示します。言語判定で編集モードやファイル内のコードを実行しません。BOM付きUTF-32は本文プレビューにも対応します。

動画・音源と一部画像の詳細には、PATH上の `ffprobe` があれば使用します。追加インストールは自動では行いません。ない場合は基本情報のみ表示し、`ffprobe not installed` と案内します。動画・音源の再生機能はありません。

取得は非同期で、同時に1プロセス、5秒、出力64 KiBまでです。選択変更や画面終了時に中止し、古い選択の結果は表示しません。結果はファイルのサイズ・更新日時などをキーに最大32件保持し、画面サイズ変更では再取得しません。`g` での再読込とレイアウト終了時にキャッシュを解放します。破損ファイルやタイムアウトでは、基本情報を残して `Details unavailable` と表示します。

### CLIP・PSD・PSB

GUI版Emacsでは、これらのファイルを選ぶと右ペインに保存済みの画像を表示します。ImageMagick、Python、Dirvish、Dired Previewの追加導入は不要です。

| 形式 | 読み取る画像 | 必要なEmacsの機能 |
| --- | --- | --- |
| `.clip` | 埋め込みSQLiteの `CanvasPreview.ImageData` | SQLite、PNG表示 |
| `.psd` / `.psb` | 埋め込みJPEGサムネイルを優先。なければ保存済み合成画像 | JPEG、またはPBM/PPM表示 |

サムネイルのないPSD/PSBは、8bit RGB・グレースケール、raw/RLE圧縮、最大64メガピクセルに対応します。透明部分は市松模様で表示し、長辺768ピクセルまで縮小します。レイヤーを再合成する機能はありません。サムネイルがなく、16/32bit・CMYK・ZIP圧縮などの場合は未対応の理由を表示します。

抽出には、同じEmacs実行ファイルを `-Q --batch` で起動した別プロセスを使います。処理中もDiredを操作でき、選択変更・画面終了時には抽出をキャンセルします。30秒でタイムアウトし、ファイルが破損している場合や必要な機能がない場合は、右ペインに理由を表示します。

元ファイル全体には通常画像の8 MiB制限を適用しません。代わりに、抽出画像には `neo-diredy-image-bytes`、1回のバイナリ読込には32 MiB、CLIPのSQLiteコピーには512 MiBの上限があります。サムネイルのない巨大なPSD/PSBは、合成画像の読込上限で表示できない場合があります。

抽出結果は更新日時・サイズなどをキーに、最大8件・合計32 MiBまでメモリに保持し、レイアウトを閉じると解放します。抽出中の一時ファイルも終了・キャンセル時に削除します。

## 検証と性能

次のコマンドをパッケージのディレクトリで実行してください。ユーザーのinitや既存セッションは読み込みません。

```powershell
emacs -Q --batch -l tests/neo-diredy-tests.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -l tests/neo-diredy-art-tests.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -l tests/neo-diredy-metadata-tests.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -l tests/neo-diredy-interop-tests.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -l tests/neo-diredy-details-tests.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -l tests/neo-diredy-modeline-tests.el -f ert-run-tests-batch-and-exit
emacs -Q --batch -l tests/check-package.el
emacs -Q --batch -l benchmarks/run.el
```

Evil連携のキー操作も確認する場合は、既存パッケージを読み取り専用で使用できます。隣の `emacs.d/elpa/`、または環境変数 `NEO_DIREDY_TEST_ELPA` で指定したディレクトリを参照し、インストールやユーザーinitの読込は行いません。

```powershell
emacs -Q --batch -l tests/neo-diredy-evil-tests.el -f ert-run-tests-batch-and-exit
```

テスト用データは `tests/` 内、計測用データは `.bench/` 内に一時作成し、実行後にその実行で作ったディレクトリだけを削除します。計測では2,100件の一覧を使います。隣に `emacs.d/lisp/` がある場合は、その実際のソース一覧も読み取りのみで計測します。

連携テストは、隣に `neo-git/`・`neo-task/` があればそのソースを読み取り専用で使います。Neo Gitは一時Gitリポジトリで起動と終了を検証し、neo-taskは一覧取得をテストデータに置き換えて画面だけを検証します。実台帳やネイティブ端末は起動・更新しません。

計測結果と改善内容は [benchmarks/RESULTS.md](benchmarks/RESULTS.md) を参照してください。バッチ計測は描画時間や実キー入力の遅延を含みません。
