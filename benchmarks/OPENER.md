# Openerの表示時間 — 2026-11-09

Windows / Emacs 31.1の隔離GUIで、`neo-diredy-open` の開始から最初の描画を経てキー入力待ちに入るまでを計測する。比較元は `258c896`。各プロセスで12回開き、前後を交互に3組測定した。

| 測定項目 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 初回表示 | 33.9 ms | 34.7 ms |
| 2〜12回目の表示 | 31.5 ms | 8.1 ms |
| 12回の表示で生成した子フレーム | 12個 | 1個 |

時間は3組の中央値。繰り返し表示は各組の11回の中央値を比較しており、約74%短縮した。初回表示の改善は確認していない。

導入済み設定と同じ `neo-edgerunners` テーマと `HackGen Console NF` 14ptを使用した。ユーザーinit全体は読み込まず、ディレクトリ集計・Git取得は無効、対象は一時ディレクトリ内のローカルファイル、候補は標準の2件。物理キーの入力処理とWindowsによる画面転送の完了時間は含まない。起動中のユーザーEmacsへの接続はできなかったため、その環境全体の遅延解消を証明する測定ではない。

毎回の子フレーム生成・初回描画が時間の大半を占めたため、有効なレイアウトにつき1つの非表示フレームと空の専用バッファを再利用する。表示位置・候補・幅・フォント・色は次回表示時に更新し、終了時は両方を破棄する。メニューを閉じるたびにフレームを破棄する処理を省くため、改善対象は2回目以降。初回とレイアウトを開き直した直後は新規生成する。

生データは [results-opener-2026-11-09.json](results-opener-2026-11-09.json)。各回の値、読み込んだソースのSHA-256、子フレーム生成数を含む。

## 再計測

必ず新しいGUIプロセスで実行する。計測後にそのEmacsを終了する。

```powershell
emacs -Q -l benchmarks/opener.el
```

既定では作業ツリーのソースを読み、`.bench/opener-latency/result.json` に出力する。比較用の環境変数は以下のとおり。

- `NEO_DIREDY_SOURCE`: 比較する `.el` のパス
- `NEO_DIREDY_RESULT`: JSONの出力先
- `NEO_DIREDY_FONT`: フォント（今回は `HackGen Console NF-14`）
- `NEO_DIREDY_THEME`: テーマ名（今回は `neo-edgerunners`）
- `NEO_DIREDY_THEME_DIRECTORY`: テーマファイルのディレクトリ
